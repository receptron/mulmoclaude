## ひとことで言うと

**コレクションは、Claude に作ってもらう自分専用の小さなアプリです。**

「行きたいお店を記録したい。店名、ジャンル、行ったかどうか、評価を付けたい」と話すと、
Claude がそのとおりの入力欄を持った表を作ります。できたものは、

- **表**で一覧でき、並べ替えや検索ができる
- 日付があれば **カレンダー**で見られる
- 「未着手 / 進行中 / 完了」のような選択肢があれば **カンバン**（カードを列の間でドラッグする画面）で見られる
- 「未完了のものを通知する」「支払日の 10 日前に知らせる」といった**お知らせ**が付けられる
- 「請求書を作って」のような**ボタン**を付けて、押すと Claude が作業する
- 自分でデザインした**カスタムビュー**（見た目を自由に作った画面）で表示できる

しかも、作ったあとに「メモ欄を足して」「評価は行ったあとだけ付けたい」と話せば、形がその場で変わります。
これを MulmoClaude では **vibe crafting**（話しながら道具を作る）と呼んでいます。

## 中身は「設計図」と「記録」だけ

コレクションは、次の 2 つでできています。

| | 何か | 例 |
|---|---|---|
| **設計図** | どんな項目があり、どう見せるかを書いたファイル `schema.json` | 「店名は文字、評価は 1〜5 から選ぶ」 |
| **記録** | 1 件ごとに 1 つのファイル（`<ID>.json`） | `ramen-taro.json` の中に 1 軒分の情報 |

データベースのソフトは使っていません。**フォルダとファイルがそのままアプリ**になっています。
だから、中身を普通のファイルとして見たり、バックアップしたり、人に渡したりできます。

設計図の中身を知りたい人は [schema.json のしくみ](schema.md) を読んでください。
知らなくても、コレクションは作れますし使えます。

## ファイルはどこにある？

ワークスペース（ふつうは `~/mulmoclaude`）の中に、次のように置かれます。

```text
~/mulmoclaude/
├── data/
│   ├── skills/
│   │   └── restaurants/          ← コレクション本体（設計図など）
│   │       ├── SKILL.md          ← Claude 向けの説明書
│   │       ├── schema.json       ← 設計図
│   │       ├── views/            ← カスタムビュー（あれば）
│   │       └── templates/        ← ボタンを押したときの指示文（あれば）
│   └── restaurants/
│       └── items/                ← 記録。1 件 1 ファイル
│           ├── ramen-taro.json
│           └── sushi-hana.json
└── .claude/skills/restaurants/   ← 本体の写し（MulmoClaude が自動で作る）
```

{: .note }
`.claude/skills/` の中は MulmoClaude が自動で作る写しです。手で書き換えないでください。
設計図を変えたいときは、Claude に頼むのがいちばん確実です。

コレクションのフォルダ名（例: `restaurants`）を **slug（スラッグ）** と呼びます。
画面の URL にもなり、`http://localhost:3001/collections/restaurants` で開けます。

## Claude はどうやって作り方を知っているの？

MulmoClaude は、起動するとワークスペースの `config/helps/` に「コレクションの作り方」の手引きを置き、
Claude はそれを読んでから設計図を書きます。設計図は書き込む前に自動でチェックされるので、
壊れた設計図がそのまま保存されることはまずありません。
