# Shared Utilities Catalog

> **Before writing a new helper, check this list.** If a similar helper already exists, use it. When you add a new shared helper (a cross-cutting formatter, error normaliser, path joiner, etc.) append a 1-line entry here in the same PR.

Skipping this step is how `truncate()` ended up with 6 implementations, `formatBytes()` with 2 + an inline copy, and the `err instanceof Error ? err.message : String(err)` pattern with ~65 inline copies plus 14 named implementations across 4 behaviours (#2217). The catalog is the prevention mechanism. (Tracking: #1304.)

This catalog only covers **cross-cutting** helpers — formatters, error helpers, network wrappers, path joiners, shared regex. One plugin's parser or one route's validator stays inside that plugin / route; it doesn't belong here.

## Known duplicates — read before "just adding one more"

The catalog's own failure mode is listing **one** member of a family and hiding
the rest, which is how `errorMessage` reached 14 implementations while the entry
above named 2 (#2217). This section names every family that still has more than
one live implementation, so a fix can be applied to all of them instead of the
first one grep happens to find.

**Architecturally forced vs. accidental:** `packages/core` cannot import from
`server/`, and plugins cannot import each other — so *some* second copy is
unavoidable. A plugin with no `@mulmoclaude/core` dependency is only *soft*
forced: adding the dep would resolve it. Everything marked accidental has no
rule requiring it.

## Adding a new shared helper

1. **Search first.** Grep this catalog and the relevant directory for an existing helper. Reaching for a generic name (`truncate`, `format`, `parse`) often surfaces a near-match.
2. **If nothing fits, write the helper** in the appropriate location (`server/utils/...` for server, `src/utils/...` for frontend). Co-locate with similar helpers; don't make a new top-level file unless it's a new area.
3. **Add tests** under `test/` mirroring the source path.
4. **Append one line to this catalog** in the same PR, under the right area. The entry shape is `path` — `helper(signature)` — one-line "when to use".
5. **If your helper supersedes scattered call sites,** include the migration in the same PR when it's small (< ~5 sites) or open a follow-up refactor issue for larger sweeps.
6. **Check the duplicates table above.** If the helper you're touching is listed there, fix *every* copy or say in the PR which ones you deliberately left and why — that table exists because fixing only the first grep hit is how these families grew.
